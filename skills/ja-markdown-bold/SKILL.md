# 日本語Markdownの太字（強調）ルール

## なぜ必要か

CommonMark系のレンダラ（GitHub・Zenn・多くのMarkdown処理系）は `**` の開閉を前後の文字種で判定する
（フランキング規則）。全角約物（`）` `。` `、` `「」` `！` `？` 等）は
Unicode句読点として扱われるため、日本語文中では以下が**太字にならない**：

- 閉じ `**` の直前が約物で、直後に文字が続く: `**描画層（案）**を足す` ← 太字にならない
- 開き `**` の直前が文字で、直後が約物: `本Issueは**「描画層」**の話` ← 太字にならない

行末・スペース前で閉じる場合は約物が隣接していても正しく描画される。
壊れるのは**文中**で約物が `**` の内側の端に来るケース。

## ルール（どちらかを適用）

1. **推奨: `**...**` の外側を半角スペースで囲む**
   `本Issueは **描画層（可読な中間表現）** を足す話`
2. **約物を太字の外に出す**（太字の端を文字・数字で始めて終える）
   `本Issueは**描画層**（可読な中間表現）を足す話`

## 書いた後のチェック

日本語Markdownに `**` を使ったら、確定（ファイル保存・投稿・返信）前に次のパターンが無いか確認する：

- `約物**文字` … 閉じ側が壊れる（例: `）**を`）
- `文字**約物` … 開き側が壊れる（例: `は**「`）

機械的に確認する場合（フランキング規則を正しく判定し、誤検出しない）:

```bash
python3 ~/.claude/hooks/ja-check/check-md-bold.py < 対象ファイル
```

スクリプトは `str | None` 型注釈を使っており **Python 3.10 以上が必須**。
`python3 --version` が 3.9 以下（例: macOS 標準の `/usr/bin/python3`）の環境では
`TypeError` で落ちるため、3.10 以上の `python3`（pyenv・mise・Homebrew 版など）を
明示的に指定して実行すること。

NG行が出力されたら（exit 1）、ルール1か2で書き直してから確定する。
なお同じ判定は ja-check フックが `.md` への書き込み時と `gh issue/pr` 投稿前
にも自動実行するため、このスクリプトはチャット返信など手前で確認したい
場合に使う。
